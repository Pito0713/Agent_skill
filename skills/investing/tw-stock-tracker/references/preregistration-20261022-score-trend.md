# 預先登錄：分數趨勢假設（2026-10-22）

> 狀態：**草稿，待使用者確認凍結**。凍結後才抽樣、跑回測；結果出來前不得改本檔的任何條件。
> 依據：ADR-026 的調權重門檻精神（獨立標的、前後兩半同號、在未參與挑選的資料上有效）。

## 1. 為什麼要測

使用者要「每天評分 + 看分數趨勢」來比較是否可以進場。但回測已證明**單日總分**和運氣分不開（ADR-026、ADR-029），
把無預測力的分數畫成趨勢線，不會自動變得有預測力。本假設檢驗：**分數往上走的標的，之後報酬是否較好**。
檢驗通過前，每日評分的趨勢與排行一律標示「未驗證」。

## 2. 已看過的資料（揭露，避免假裝沒看過）

- 已看過：run 1（自選 21 檔）、run 2（臺灣 50）、run 4（新抽 60 檔）的總分與分項 Rank IC、
  run 4 依趨勢拆開的回檔分數 IC
- **未看過**：任何一組的 Δ分數（分數變化量）IC。本檔凍結前不計算
- 已知相關性：Δ分數必然與近 4 週的價格變化相關（趨勢、乖離、MACD 都隨價格移動），
  本測試結果可能等同於在測「短期動能／反轉」，判讀時須與 run 1、2、4 的乖離分項結果一起看

## 3. 假設與定義

- **原始總分**：六項原始加總 `s_trend + s_bias + s_support + s_volume + s_macd + s_rsi`，不含硬規則壓分
- **Δ分數**：同一標的、同一 run，本週樣本的原始總分 − 4 週前樣本的原始總分。
  「4 週前樣本」= 該標的 `as_of` 落在〔本週 as_of − 35 天，本週 as_of − 21 天〕之間、最接近 −28 天的那筆；
  沒有則該筆排除（各標的最初約 4 週必然排除）
- **報酬**：`horizon_days = 14` 的 `tradable_return_pct`（次一交易日開盤進場、扣成本），
  `tradable_excluded_reason` 非 NULL 者排除
- **IC 與 t 值**：沿用 `backtest_stats.weekly_ic` 逐週橫斷面 Rank IC、`summarize_ic` 的重疊修正 t 值，不另寫統計方法
- **H1（主假設）**：新標的的 Δ分數與 14 天可成交報酬的 Rank IC 為正
- **H2（附帶，只記錄）**：新標的上 Δ分數 IC 的 t 值高於原始總分 IC 的 t 值（趨勢比單日分數更有資訊）
- 每日評分的「5 日 Δ」不在本次檢驗範圍，只供顯示

## 4. 樣本

- **樣本外標的（新）**：從 `stock_names` 抽 60 檔普通股（4 碼數字、首碼非 0，即排除 ETF），
  排除資料主機 `backtest_runs` 中 run 1、run 2、run 4 的 `tickers` 欄位所列全部標的；上市、上櫃都抽。
  候選清單依代號排序後以 `random.Random(20261022).sample` 抽取
- 抓取或評分失敗者直接略過、**不補抽**；有效標的少於 40 檔 → 判定「樣本不足」，不下結論
- **期間**：與 run 1、2、4 相同的 3 年（2023-10 ~ 2026-10），每週一次。前後兩半以樣本中位評估日切分
- **主要期間**：持有 14 天、可成交口徑。7 天、30 天只記錄，不參與判定

## 5. 判定標準（全部滿足才算通過）

1. 新標的 Δ分數 Rank IC **t ≥ +2**
2. 新標的的前後兩半，該 IC 都為正
3. run 1、run 2、run 4 各自計算同口徑 Δ分數 IC，**沒有任何一組 t ≤ −2**

- 全部通過 → 每日評分的「20 日 Δ」與排行可移除「未驗證」標示；**不改總分、不改權重**
- 任一未過 → 假設不成立，趨勢與排行維持「未驗證」標示

## 6. 不論結果都要做

- 結果寫進 `scoring-rubric.md` 的回測證據段與 ADR-030，未通過也要記
- **不在同一批資料上試第二個變體**（改 Δ 週數、改持有期、改定義）。新想法要重新登錄，並換一組沒用過的標的
- 已知限制：期間與 run 1、2、4 重疊（只有標的是樣本外，時間不是）；抽樣用現存標的，有存活者偏差；
  Δ 以週樣本計算，與每日評分的 20 個交易日 Δ 近似但不完全相同

## 7. 執行（凍結後）

1. commit 本檔
2. 在資料主機依 §4 抽樣，把清單附在本檔末尾（另一個 commit）
3. `python3 backtest.py run --years 3 --tickers <清單>`（逐月抓日線，每次間隔 3 秒，預估 2 小時以上，只在資料主機執行）
4. 依 §3、§5 計算並回報；分析 script 放 scratchpad，不進 repo
