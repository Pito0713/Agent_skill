# 三模式輸出模板

> 每則資訊都要能追到來源。來源標記共四種：
> `[vault]` 你的筆記 ｜ `[ref]` 本 skill references ｜ `[web]` 網搜來的外部資料 ｜ `[model]` 我的一般知識
>
> **`[web]` 與 `[model]` 的內容你沒驗證過，涉及比例與時間時要說出這件事。**

---

## 模式 A：食譜產生

```markdown
## <菜名>　<份數>人份　約 <分鐘> 分鐘

**限制確認**：<過敏原 / 飲食限制 / 設備>　←（開場三問的回覆，原樣覆述）

### 食材
| 食材 | 用量 | 備註 |
|------|------|------|
| ... | ...（scale.py 輸出）| |

> 份量由 `scale.py recipe` 計算，factor = <值>

### 步驟
1. ...（每步標出可判斷的完成訊號，例如「炒到邊緣透明」而非「炒香」）
2. ...

### 關鍵控制點
- <火候／溫度／時間，以及最容易失敗的那一步>

### 來源
- 主結構：[vault] <筆記路徑> ／ [model]
- 替代建議：[ref] substitutions.md
```

## 模式 B：冰箱反查

```markdown
## 你有的：<食材清單>

**想吃哪個味型？** <從 flavor-pairing.md 挑 2–3 個可行方向讓使用者選>

### 方案 1：<菜名>（味型：<台式／日式…>）
- 四槽對照：鹹 <X> ／ 鮮 <X> ／ 酸甜 <X> ／ 香 <X>　[ref] flavor-pairing.md
- **缺**：<沒有的食材>
- **可替代**：<替代品 + 換掉會變什麼>　[ref] substitutions.md
- **不可替代**：<標 ⚠️ 的項目，說明為什麼不行>

### 方案 2：...

### 需要先處理掉的食材
<快壞的先用：葉菜 → 海鮮 → 絞肉 → 根莖 → 冷凍>
```

## 模式 E：週餐規劃

```markdown
## <N> 天菜單

| 日 | 菜色 | 共用食材 | 備料 |
|----|------|----------|------|
| ... | ... | ... | ... |

### 採購清單
<直接貼 shopping_list.py 的輸出，不要重打>

### 食材消耗順序
<易壞的排前面：葉菜 → 海鮮 → 絞肉 → 根莖 → 冷凍>

### 這份菜單的取捨
<說明為什麼這樣排：共用了哪些食材、避開了什麼浪費>
```

---

三模式輸出結束後都要問一次要不要存進 vault，格式與規則見 `SKILL.md` 的「vault 寫入鉤子」。
