# Information Architecture

規劃使用者找到資訊的路徑，適用於前端導航設計與 API 路由結構規劃。

## 執行步驟

[ ] Step 1：內容盤點 - 列出所有需要呈現的功能 / 頁面 / 資源 - 確認哪些是使用者最常用的（高頻）

[ ] Step 2：選擇架構模式

    | 模式 | 特徵 | 適用場景 |
    |------|------|---------|
    | 階層式 | 樹狀，父子關係明確 | 大多數網站、後台管理 |
    | 資料庫式 | 多維度篩選 | 電商、搜尋結果、內容平台 |
    | 線性式 | 固定順序 | 表單流程、onboarding、教學 |
    | 矩陣式 | 使用者自訂路徑 | 維基、知識庫 |

[ ] Step 3：定義層級（最多 3-4 層）

    ```
    層級 1（全域導航）：5-7 項
    層級 2（子導航）：每項下 3-6 項
    層級 3（頁面內錨點）：非必要
    ```

[ ] Step 4：命名原則 - 使用使用者語言，不用系統術語 - 動詞開頭（「新增訂單」而非「訂單管理」）- 名稱不重複，不歧義

[ ] Step 5：驗證 - 任何內容能在 3 次點擊內到達嗎？- 命名是否讓初次使用者也能理解？

## 輸出格式

樹狀結構圖：

```
首頁
├── 產品
│   ├── 所有產品
│   ├── 依類別瀏覽
│   └── 新品上架
├── 帳號
│   ├── 個人資料
│   ├── 訂單紀錄
│   └── 設定
└── 幫助中心
```
