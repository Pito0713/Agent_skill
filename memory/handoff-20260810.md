## 重要決策

| 決策 | 選擇 | 原因 |
|------|------|------|
| description 門檻 | 維持 **400** | 實測未 waiver 的 30 個中位數 191、最大 386，門檻沒在擋人 |
| 固定開場成本上限 | **30,000**（現值 25,432） | 約 18% 餘裕；真正成長風險在常駐 rules 那 14,671，不是 skill 數量 |
| 預算超標怎麼辦 | **具名說明制，不影響 exit code** | 擋住正常工作不是目的；硬牆會在正當成長時誤傷 |
| `--strict` | 預設仍 exit 0，加旗標才 exit 1 | 日常查看報表不受干擾，CI / pre-commit 才要牙 |
| waiver 格式檢查放哪 | `token_budget_spec.py` 單一定義，report 與 validator 共用 | 兩邊各寫一份就是新的漂移源 |
| `metadata.trigger` | 定義為人類備註欄，不同步不檢查 | 刻意的職責分離，不是待修的漂移；另兩個選項要動 38 份檔案 |
| 移除失效 waiver 的權限 | 🟢（修正事實錯誤）；新增/修改仍 🟡 | 否則 stale waiver 出現後沒人能讓 `--strict` 恢復通過 |

## 已知問題 / 風險

- ⚠️ **waiver 格式檢查證明不了核准真的發生過**——repo 內沒有任何東西能證明。它的作用是提高
  「隨手塞字串把警告弄不見」的成本 + 讓 grep 稽核可行。§8.3 已誠實寫明，不要有人日後
  誤以為它是授權機制
- ⚠️ **`--strict` 尚未掛進 pre-commit**。§8.6 說它「是給 pre-commit 與 CI 用的」，但實際
  掛載沒做——目前靠人記得跑。要掛的話動 `hooks/pre-commit-audit.sh`
- ⚠️ **測試硬釘 baseline 檔名**。這是刻意的（成本偏離基準就該紅掉逼人決定），但日後若真的
  接受了新的成本水位，要同時改測試裡的路徑與 §8.4 的說明
- ⚠️ `governance/backups/` 已有 1 份備份，§5 規定超過 10 份要問使用者清理
