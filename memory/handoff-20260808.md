## 重要決策

| 決策 | 選擇 | 原因 |
|------|------|------|
| 採集方式 | 事後挖 transcript / rollout，**不裝 hook** | 零 runtime 成本、可回溯、不新增自動寫入路徑；Codex 的 `hooks.json` 為空且不分發，hook 路線兩邊不對等 |
| 指標結構 | `inv` / `read` / `edit` **三個永不合併** | 「讀到」不等於「選用」——用 `code-review` 會連帶讀 `coding-workflow-core`。合成單一 usage 數等於把效度問題藏起來 |
| usage vs maintenance | 寫入類看作用目標；明確調用一律算 usage；**workdir 缺失或在本 repo 內一律進 `?` 不猜** | v1 用 cwd 判定，實測 158 個 call 中 21 個 session cwd ≠ workdir、20 個缺 workdir |
| 首版要不要分層 | **不分層、不貼退場標籤** | Codex 用 v1 規則實算：半數 skill（含 `deploy-prep`、`security-review`）會被丟進退場評估，且「沉睡」層完全空置 |
| 外部 skill 名稱處理 | **不做 alias 合併**，一律進 `unresolved` | Codex 建議把 `anthropic-skills:coding-workflow`(9 次) 映射到本 repo 的 `coding-workflow`。查 `~/.claude/plugins/` 無對應項目，是外部 marketplace 命名空間，合併等於把別人的使用記到自家頭上 |
| feedback 自主 append 的權限 | **必須先明文改協議**，不得「比照 lessons.md」 | v1 寫「比照 🟢 級」是模型自行擴權，正是 `maintenance-protocol §1` 要防的事（Codex BLOCKER 4） |
| Phase 2 要不要等資料 | **不用等** | 統計可回溯（transcript 還在，晚挖零損失），feedback 不可回溯（當下的判斷過了就沒了）。gate 問的三題全在問統計可不可信，與 feedback 無關 |
| 腳本拆兩檔 | CLI 與抽取分離 | 單檔 366 行，超過 `coding-standards.md` 的 300 行上限 |
