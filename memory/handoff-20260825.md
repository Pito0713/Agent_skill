## 重要決策

| 決策 | 選擇 | 原因 |
|------|------|------|
| 停用資料夾放哪 | repo 根的 `deprecated/`，**不在 `skills/` 內** | validator 用 `skills/**/SKILL.md` 與 index 雙向比對，放進去直接 FAIL |
| 用 `lifecycle: deprecated` 標記可不可以 | **不行** | link farm 照 index 建 symlink，標記改變不了可見性；停用必須是**移出索引** |
| 被停用 skill 的委派點 | 內聯精簡版（使用者裁決） | 保留能力又斷開依賴；留指向 `deprecated/` 的路徑等於沒停用 |
| 學術路由 | 收斂到四個專科 mentor，都不匹配走一般回答（使用者裁決） | `academic-mentor` 兜底角色與四專科重疊，0 次主動選用 |
| 合併後的搜尋 skill 命名 | 新名 `knowledge-search` | `rag-search` / `obsidian-query` 皆只描述一半；兩者觸發詞全數併入 |
| 被合併掉的 5 份原檔 | 也進 `deprecated/`，不刪 | 與使用者「當作文檔放著」的意圖一致 |
| 測試裡的常數 | 描述現況的導出、守門檻的才寫死 | 見 lessons 2026-08-25 第二條 |

## 已知問題 / 風險

- ⚠️ **使用統計不能單獨當停用依據**：窗口約 3 週、agy 完全未涵蓋、`critical-on-demand`
  類（`deploy-prep` / `security-review`）本來就低頻。本輪只動「另有功能重疊證據」的項目，
  純低頻的一律不碰。日後要再汰除**必須重跑統計並重新裁決**，不要照這份清單類推。
- ⚠️ **`deprecated/` 內的 12 份不再受 validator 與 token-budget 涵蓋**，會隨制度演進逐漸過時。
  復用前必須重讀內容，不可直接搬回。
- ⚠️ **`obsidian-save` 的 mentor 來源偵測靠區塊標題**（【定位聲明】【機制鏈】等），本輪已同步
  改為四個專科 mentor；日後動 mentor 區塊標題仍會靜默斷掉這條依賴，沒有自動檢查。
- ⚠️ **五份 mentor 摘要之間可能各自漂移**（沿自 ADR-022），同步清單在
  `_shared/mentor-protocol.md` §9，純自律。
